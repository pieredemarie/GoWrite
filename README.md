# GoWrite

Сервис для публикации коротких статей в формате Markdown — минималистичный аналог [Telegraph](https://telegra.ph). Без регистрации: написал текст, опубликовал, получил ссылку.
Протестировать приложение с простой клиентской частью можно здесь: https://gowrite-frontend.vercel.app/


## Идея

- Пишешь статью в Markdown → публикуешь → получаешь **публичную ссылку** на чтение
- Право на редактирование определяется **секретным токеном**, который выдаётся один раз при публикации — никаких аккаунтов и паролей
- Редактирование — по секретной ссылке или автоматически в том же браузере (токен сохраняется локально)

## Стек

**Backend**
- Go (`net/http`, паттерны маршрутизации Go 1.22+)
- PostgreSQL (`pgx` в качестве драйвера `database/sql`)
- [`goldmark`](https://github.com/yuin/goldmark) — рендер Markdown → HTML
- [`bluemonday`](https://github.com/microcosm-cc/bluemonday) — санитайзинг HTML
- Docker / docker-compose

## Архитектура

```
Client (React SPA)
      │
      │  REST API (JSON)
      ▼
Go HTTP-сервер
  ├── handler   — HTTP-слой, парсинг запросов, коды ответов
  ├── service   — бизнес-логика: генерация slug/токена, рендер markdown, валидация
  └── repository — доступ к PostgreSQL
      │
      ▼
  PostgreSQL
```

Модель авторства без аккаунтов: при публикации сервер генерирует случайный `slug` (публичный идентификатор статьи) и случайный `edit_token` (секрет). В базе хранится только SHA-256 хэш токена — сырой токен отдаётся клиенту один раз и никогда больше не восстанавливается. Любая операция изменения (`PUT`/`DELETE`) требует токен в заголовке `X-Edit-Token` 

## API

| Метод | Путь | Заголовки | Тело | Ответ |
|---|---|---|---|---|
| `POST` | `/api/articles` | — | `{title, content_md}` | `201` `{slug, token}` |
| `GET` | `/api/articles/{slug}` | — | — | `200` статья / `404` |
| `PUT` | `/api/articles/{slug}` | `X-Edit-Token` | `{title, content_md}` | `200` / `403` / `401` |
| `DELETE` | `/api/articles/{slug}` | `X-Edit-Token` | — | `204` / `403` |

## Запуск локально

Требуется Docker и Docker Compose.

Backend поднимется на порту, указанном в `.env` (`PORT`), база — в отдельном контейнере, таблица создаётся автоматически из `migrations/init.sql` при первом запуске.
